# Quid-App — contexto del proyecto

## Qué es
Aplicación financiera personal (Next.js + Prisma + PostgreSQL).
Módulos interconectados: Finanzas, Transporte, Salud, Despensa.
Enfoque Colombia — moneda COP, bancos colombianos, precios locales.
Auditoría, optimización e implementación de una financiera personal.

## Tecnologías
- **Frontend:** Next.js (App Router), TypeScript, Tailwind + shadcn/ui, React
- **Backend:** Next.js API (server actions, routes), Prisma ORM
- **Base de datos:** PostgreSQL (via Prisma)
- **Infra:** Docker Compose (postgres, ollama según config)
- **Moneda:** COP (cuando no se especifique otro)

## Módulos y sus entidades principales (mirá prisma/schema.prisma antes de tocar cualquier tabla)

### Finanzas
Transaction, Budget, Debt, Abono (deuda), SavingsGoal, CDT, RecurringPayment,
Category, CategoryRule, Account, SharedAccountUser, AccountInvitation,
PayrollGroup, FuelPrice (también usado por Transporte), CreditCardTransaction...

### Transporte
Vehicle, VehicleReminder, MaintenanceServiceRule, FuelPrice.
→ El FuelPrice de Transporte puede impactar Finanzas — si se modifica, verificar si hay reglas o transacciones dependientes.

### Salud
Medication, MedicalAppointment, MedicalOrder, MedicalAuthorization,
HealthProfile, HealthAiReport, MaintenanceServiceRule (comparte modelo con Transporte).

### Despensa
PantryItem, ShoppingList, Recipe, PriceHistory, PantryMovement.
Seguimiento de inventories, precios históricos, listas de compra.

### Entidades transversales
User (base), Notification (AppNotification), Category (usada por Transacción),
Address, Attachment — aparecen en múltiples módulos.

## Reglas generales
- **Nunca tocar la DB sin leer el schema primero.** Mirá `Quid-App/prisma/schema.prisma`.
- **Fuel de Transporte fluye a Finanzas** — si agregás/modificás combustible, checkear impacto.
- **Moneda default: COP.** No asumir USD ni otro.
- **Horas: Colombia (UTC-05).** No asumir otra timezone en calculos de fechas.
- **App en producción usa Next.js compilado** — cambios en `src/` requieren rebuild o dev server.
- **El proyecto es un monorepo** — la app vive en `Quid-App/`, no en la raíz.
- **Documentación existente:** `worklog.md` (bitácora), `IDEA.md` (idea central), `nuevas ideas para la app.md`.
